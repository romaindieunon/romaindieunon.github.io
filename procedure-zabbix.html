Zabbix — Installation du superviseur (VM Sigma)

Mise en place d'une VM Debian 13 (Trixie) sous Proxmox VE pour héberger un superviseur Zabbix 7.0 LTS. La machine, nommée Sigma, s'intègre au réseau du projet BTS SIO à l'adresse 192.168.200.205 dans le VLAN Serveurs (200) et vient compléter le parc supervisé.

SolutionZabbix 7.0 LTS
OSDebian 13 (Trixie)
HyperviseurProxmox VE — nœud Gamma
Nom de la VMSigma
VM ID205
Base de donnéesMariaDB / MySQL
Frontal webApache 2 + PHP
IP du serveur192.168.200.205/24
Passerelle192.168.200.250
VLAN200 — Serveurs
DomaineBTSSIO.RD
Interface adminhttp://192.168.200.205/zabbix

Étape 1 — Création de la VM Sigma sur Proxmox

Création d'une nouvelle machine virtuelle sur le nœud Proxmox Gamma via l'assistant Create VM. La VM est dimensionnée pour accueillir le serveur Zabbix, sa base de données MariaDB et le frontal web Apache.

1.1 — Onglet General : identification de la VM

  • Node : Gamma
  • VM ID : 205 (cohérent avec la dernière octet de l'IP)
  • Name : Sigma

1.2 — Onglet OS : choix de l'ISO Debian 13

  • Use CD/DVD disc image file : stockage local
  • ISO image : debian-13.2.0-amd64-netinst.iso
  • Guest OS Type : Linux — Version 6.x - 2.6 Kernel

1.3 — Onglet System : agent QEMU

  • Graphic card : Default
  • Machine : Default (i440fx)
  • BIOS : Default (SeaBIOS)
  • SCSI Controller : VirtIO SCSI single
  • Qemu Agent coché (permet à Proxmox de communiquer avec la VM pour les snapshots et l'arrêt propre)

1.4 — Onglet Disks : disque système 20 GiB

  • Bus/Device : SCSI 0
  • Storage : local-lvm
  • Disk size : 20 GiB
  • IO thread : activé (améliore les performances I/O)

1.5 — Onglet CPU : 2 cœurs

  • Sockets : 1
  • Cores : 2 (total : 2 vCPU)
  • Type : x86-64-v2-AES

1.6 — Onglet Memory : 2 Go de RAM

  • Memory (MiB) : 2048 (suffisant pour Zabbix 7 + MariaDB en lab)

1.7 — Onglet Network : bridge vmbr0

  • Bridge : vmbr0 (pont par défaut vers le LAN du projet)
  • Model : VirtIO (paravirtualized)
  • VLAN Tag : no VLAN (la VM reste dans le VLAN natif du bridge)
  • Firewall : coché

1.8 — Onglet Confirm : récapitulatif

Vérification de l'ensemble des paramètres avant création.

Étape 2 — Installation de Debian 13 (Trixie)

Démarrage de la VM Sigma sur l'ISO Debian. Choix de l'installation graphique et déroulement de l'assistant.

2.1 — Menu de démarrage : Graphical install

2.2 — Langue, pays et clavier

  • Langue : Français
  • Pays : France

2.3 — Configuration réseau manuelle

Pas de DHCP sur ce VLAN : la configuration IP est saisie à la main pendant l'installation.

  • Adresse IP : 192.168.200.205
  • Masque réseau : 255.255.255.0
  • Passerelle : 192.168.200.250 (PfSense du projet)
  • Serveurs DNS : 192.168.200.201 192.168.200.202 (les deux contrôleurs AD)

2.4 — Nom de machine et domaine

  • Nom de machine : Sigma
  • Domaine : BTSSIO.RD (domaine Active Directory du projet)

2.5 — Mot de passe root et utilisateur standard

  • Mot de passe root défini (saisi deux fois)
  • Création de l'utilisateur administrateur avec son mot de passe

2.6 — Partitionnement du disque

  • Méthode : Assisté — utiliser un disque entier
  • Disque cible : SCSI1 (sda) — 21.5 GB QEMU HARDDISK
  • Schéma : Tout dans une seule partition (recommandé pour les serveurs simples)
  • Validation puis confirmation de l'écriture sur le disque (formatage ext4 pour / et création d'un swap)

2.7 — Configuration de l'outil de paquets (APT)

  • Analyser d'autres supports d'installation : Non
  • Pays du miroir : France
  • Miroir Debian : deb.debian.org
  • Mandataire HTTP (proxy) : laissé vide

2.8 — Popularity-contest et sélection des logiciels

  • Participation à popularity-contest : Non
  • Logiciels installés : uniquement Serveur SSH + Utilitaires usuels du système
  • Tous les environnements de bureau (GNOME, Xfce, KDE, etc.) sont décochés — c'est un serveur sans interface graphique

2.9 — Installation du chargeur GRUB

Choix de l'installation manuelle de GRUB sur le disque principal /dev/sda.

2.10 — Fin de l'installation

L'installation est terminée, la VM peut redémarrer sur le système installé. L'ISO sera automatiquement détaché.

Étape 3 — Installation de Zabbix en ligne de commande

Après le premier reboot de la VM Sigma, toute la suite de l'installation se déroule en SSH (ou directement en console). Cette étape regroupe la mise à jour du système, l'installation de la pile LAMP (Apache, MariaDB, PHP), l'ajout du dépôt officiel Zabbix, l'installation des paquets Zabbix, la création de la base de données, l'import du schéma SQL et la configuration fine du serveur Zabbix, d'Apache et de PHP.

3.1 — Mise à jour du système

On commence toujours par s'assurer que le système est à jour avant d'installer de nouveaux services.

sudo apt update && sudo apt upgrade -y

3.2 — Installation d'Apache, MariaDB et PHP

On installe le serveur web Apache 2, le SGBD MariaDB et toutes les extensions PHP requises par le frontend Zabbix (mysql, gd, xml, bcmath, mbstring, curl).

sudo apt install -y apache2 mariadb-server \ php php-mysql php-gd php-xml php-bcmath php-mbstring php-curl

3.3 — Ajout du dépôt officiel Zabbix 7.0 LTS

Les paquets Zabbix ne sont pas dans les dépôts Debian. On ajoute donc le dépôt officiel Zabbix 7.0 LTS pour Debian 13 en téléchargeant et installant le paquet zabbix-release, puis on rafraîchit les caches APT.

wget https://repo.zabbix.com/zabbix/7.0/debian/pool/main/z/zabbix-release/zabbix-release_latest+debian13_all.deb sudo dpkg -i zabbix-release_latest+debian13_all.deb sudo apt update

3.4 — Installation des paquets Zabbix

Installation du serveur Zabbix (lié à MySQL/MariaDB), du frontend PHP et de l'agent local qui supervisera la VM Sigma elle-même.

sudo apt install -y zabbix-server-mysql zabbix-frontend-php zabbix-agent

3.5 — Création de la base de données Zabbix

On se connecte à MariaDB en tant que root, puis on crée la base zabbix avec le jeu de caractères imposé par Zabbix 7 (utf8mb4 + collation utf8mb4_bin), ainsi que l'utilisateur SQL zabbix avec son mot de passe et tous les privilèges sur cette base.

Note : il s'agit d'un environnement de test. Les mots de passe sont masqués dans cette procédure ; en production, j'utiliserais un mot de passe long et unique, stocké dans un gestionnaire de mots de passe.

sudo mysql

Une fois dans le prompt MariaDB :

CREATE DATABASE zabbix CHARACTER SET utf8mb4 COLLATE utf8mb4_bin; CREATE USER 'zabbix'@'localhost' IDENTIFIED BY '********'; GRANT ALL PRIVILEGES ON zabbix.* TO 'zabbix'@'localhost'; FLUSH PRIVILEGES; EXIT;

3.6 — Import du schéma initial (étape IMPORTANTE)

Le schéma SQL livré avec Zabbix (tables, index, vues, fonctions) doit être importé dans la base fraîchement créée. Sans cet import, l'assistant web échouera à initialiser l'application.

zcat /usr/share/zabbix/sql-scripts/mysql/server.sql.gz | mysql -u zabbix -p zabbix

3.7 — Configuration du serveur Zabbix

Le démon Zabbix Server doit connaître le mot de passe de la base de données. On édite son fichier de configuration et on ajoute (ou décommente) la ligne DBPassword.

sudo nano /etc/zabbix/zabbix_server.conf

Ajouter (ou décommenter) la ligne :

DBPassword=********

3.8 — Configuration d'Apache pour Zabbix (étape TRÈS IMPORTANTE)

Par défaut, Apache ne sert pas l'alias /zabbix. Il faut créer (ou compléter) la configuration zabbix.conf pour déclarer l'alias et autoriser l'accès, puis activer le frontend Zabbix.

sudo nano /etc/apache2/conf-available/zabbix.conf

Contenu à mettre :

Alias /zabbix /usr/share/zabbix <Directory /usr/share/zabbix> Require all granted AllowOverride None </Directory>

Activer la configuration et recharger Apache :

sudo a2enconf zabbix-frontend-php sudo systemctl restart apache2

3.9 — Ajustement des paramètres PHP (sinon erreur dans l'assistant web)

Zabbix exige certaines valeurs PHP plus généreuses que les valeurs par défaut, sinon l'assistant web affichera des erreurs (taille mémoire, durée d'exécution, taille d'upload). On édite le php.ini de la version PHP utilisée par Apache.

sudo nano /etc/php/8.4/apache2/php.ini

Modifier (ou ajouter) ces directives :

post_max_size = 16M upload_max_filesize = 16M max_execution_time = 300 max_input_time = 300 memory_limit = 256M

Puis redémarrer Apache pour prendre en compte les modifications :

sudo systemctl restart apache2

3.10 — Activation et démarrage des services

On active les quatre services au boot pour qu'ils repartent automatiquement après un reboot, puis on les redémarre tous afin qu'ils tournent avec la configuration finale.

sudo systemctl enable apache2 mariadb zabbix-server zabbix-agent sudo systemctl restart apache2 mariadb zabbix-server zabbix-agent

Étape 4 — Assistant web Zabbix 7.0

L'interface est désormais accessible à l'adresse http://192.168.200.205/zabbix depuis le poste d'administration. L'assistant web finalise la configuration du frontal PHP.

4.1 — Bienvenue dans Zabbix 7.0

Choix de la langue de l'interface : Français (fr_FR).

4.2 — Vérification des prérequis

Tous les prérequis PHP sont validés (xmlwriter, xmlreader, PHP LDAP, PHP OpenSSL, ctype, Session, gettext, curl, paramètres régionaux, etc.) — tout est marqué OK.

4.3 — Configuration de la connexion à la base de données

  • Type de base de données : MySQL
  • Hôte : localhost
  • Port : 0 (port par défaut)
  • Nom de la base : zabbix
  • Stocker les informations d'identification dans : Texte brut
  • Utilisateur : zabbix
  • Mot de passe : (celui défini dans zabbix_server.conf)

4.4 — Paramètres du serveur Zabbix

  • Nom du serveur Zabbix : Sigma (visible en haut à droite de l'interface une fois connecté)
  • Fuseau horaire par défaut : (UTC+02:00) Europe/Paris
  • Thème par défaut : Bleu

Étape 5 — Première connexion à l'interface

Une fois l'assistant terminé, l'écran de connexion Zabbix est affiché. La connexion s'effectue avec le compte par défaut Admin / zabbix, immédiatement suivi d'un changement de mot de passe via Users → Admin → Change password pour des raisons évidentes de sécurité.

Bilan

Le superviseur Zabbix 7.0 LTS est opérationnel sur la VM Sigma à l'adresse 192.168.200.205. Le serveur se supervise déjà lui-même grâce à l'agent Zabbix installé localement. Il est désormais prêt à recevoir les hôtes du parc (contrôleurs AD, PfSense, postes clients) via le déploiement d'agents et la création d'hôtes côté UI.

Cette procédure m'a permis de mobiliser plusieurs compétences du BTS SIO SISR : virtualisation sous Proxmox, installation d'un OS Linux serveur, configuration réseau statique, administration d'un SGBD MariaDB, gestion de paquets via dépôts tiers, et mise en service d'un outil de supervision conforme aux standards de l'écosystème open-source.
